# 渠道设置与私密填写

三个范围分别管理：

- **连接**：主机的机器人凭证、连接地址和消息选项。共享渠道的配置会影响该主机的使用者。
- **访问身份**：白名单把平台用户/群 ID 映射到 ClawCross 用户。高级设置保留手工管理入口。
- **通知目标**：每个用户接收主动推送的地址；`set_notification_channel` 不是创建机器人。Telegram 的目标是数字 chat_id，不是 token。可推送平台以 `get_notification_status` 为准。

Studio 设置与 Mobile 消息渠道提供按平台的连接表单，原始 JSON 和运行参数折叠在高级设置。WeClaw 扫码与白名单管理仍保留。保存只请求渠道重新连接，不安装组件、不会发送测试消息。

Agent 先用 `get_channel_setup(channel=...)` 查询字段，再用 `request_channel_setup` 请求对话里的表单。`values` 只接收非敏感预填；密钥、可能带凭证的 URL、程序与配置路径标为 `human_only`，由用户直接填入。所有字段取自 `config/channels.json`，不是 Agent 提供的 HTML。

表单请求绑定用户和 Agent。`request_channel_setup` 和 `request_configuration` 等待用户操作，在原工具调用中返回 `completed`（已保存）、`cancelled`（已取消）或 `expired`（等待超时），不另发 inbox 通知。默认等待 600 秒，可用 `CLAWCROSS_FORM_WAIT_SECONDS` 调整；停止对话会取消待填表单，超时后不能再保存。设置页直接创建的表单有效期仍为一天。

用户通过认证 JSON 接口提交，服务端校验字段后合并到当前渠道的第一个机器人，保留其他机器人和省略的已有凭证。请求数据库只保存非敏感草稿；提交值不存入请求表、工具结果、消息记录或通知。Agent 仅收到请求编号、最终状态与生效说明。密钥仍需存入主机配置，这是机器人工作所需；“不发给 LLM”不表示主机不存储。

没有网页的渠道不能通过普通聊天填写秘密；工具提示用户到设置页面填写。提交后只向 Agent 收件箱写入无值的状态通知。接口以认证身份查找请求，不接受跨用户提交。

验证：隔离临时目录的真实存储与认证路由测试覆盖不回显、跨用户拒绝、重复提交拒绝、旧凭证保留及嵌套邮件配置；390px/1280px 浏览器测试覆盖私密提交、保存后移除输入与不横向溢出。
