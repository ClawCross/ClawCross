# 群聊服务拆分计划与实现状态

2026-10-01：独立进程、同机多用户、密码远程加入与双向连接已在 `feature/federated-group-service` 实现。实际接口、容量与边界见 [跨设备群聊](group-network.md)。下面保留原设计参考；旧群采用兼容 RPC，不进行历史主键重写；新群身份采用服务器签发的 connection/principal。

## 当前先修好的边界

动态块区分“所属群完整列表”和“本轮来源群”，只包含群号、名称、成员、角色及发送渠道等元信息。群对话仍在 inbox 消息与摘要中。归属每次调用读取，内部使用现有动态状态差分，外部使用增量补丁。重置清除旧历史、动态基准及待投递输入；保留 agent 身份、人设、群成员关系和安全模式。

API `GET /groups?agent_id=<id>` 按当前认证用户查询其 agent 的群归属；agent 详情返回 `groups`，前端展示群名和群号。工具提供 `list_agent_groups`、`get_group_details`、`get_team_details`。发送必须有调用 agent 身份并属于目标群，可用 `expected_title` 核对群名；该核对不能判断用户真正想发哪个群。

## 第一阶段：同机多用户

1. 群成员主键改成 `(group_id, user_id, agent_id)`，人类成员也使用明确的用户字段。当前裸 agent_id 只在其 owner 空间内唯一，跨用户群不能继续只靠它辨认成员。现有数据从群 owner 补齐 user_id，兼容迁移后再允许跨用户成员。
2. 认证确定 actor_user_id；agent 所有者和发送者由可信调用凭证决定，不能仅信任正文里的 user_id。接收时同时检查群存在、用户/agent 复合身份、成员关系、禁言及发送权限。
3. 群主邀请其他用户；被邀请用户选择自己的 agent 加入。管理、读消息、发消息、@所有人分别定义权限。退出立即撤销读写及后续投递权限；测试相同 agent_id 属于不同用户的情况。
4. 转发地址使用目标 `(user_id, agent_id)`，避免按群主用户查找全部成员。独立保存每个成员的 inbox 游标；投递前复核成员关系。使用消息 ID 去重、持久化待转发队列、重试上限与失败状态，支持 agent 服务暂时离线。

## 第二阶段：独立进程（仅内网/回环）

群服务负责群元信息、成员、消息、权限、游标和转发队列；agent 服务负责执行与 agent inbox；OASIS 继续负责工作流。群服务通过 Agent API 投递，不导入任何运行时。

从启动器显式启动群服务，默认绑定回环地址。先提供 HTTP 发群/查询和轮询，再考虑 SSE 通知。Agent API 与群服务之间使用独立服务凭证，转发必须携带用户、agent、group_id、message_id 和成员版本。动态元信息接口可返回 membership_version 以便缓存失效；reset 不改变真实成员关系。

## 第三阶段：显式开放远端

配置 URL/IP 与按用户/服务范围授权的密钥，支持轮换、撤销、速率与消息大小限制、过期和重放防护；公网必须 HTTPS。不能把当前拥有全权限的 INTERNAL_TOKEN 直接当作所有远端客户端的通用密钥。默认不开公网端口、不启 tunnel。

验收：跨用户同号 agent 不串群；未加入/已退出者不能读写；重复和重放不重复转发；凭证撤销即时生效；故障恢复不漏投、不绕过权限；资源使用有界。以上三个阶段按顺序实施。
