# 严格模式与平台安全审查

日期：2026-10-04。此次检查覆盖命令后端、文件工具、Web 工具及与这些边界相关的配置入口；不是整个产品的渗透测试。没有读取真实用户私有文件或攻击线上接口。

## 定义与默认值

严格模式应作为 Agent 的安全等级，覆盖各个有能力访问宿主文件或网络的工具，不能仅给 command 加一个开关。当前选择 `sandbox_security=strict` 会强制启用命令隔离、选择独立工作区、忽略历史提权，并拒绝新增提权。文件工具和 Web 工具也执行硬限制；审批只能确认限制以内的操作。普通模式和全局默认值未改变。

这里的“严格”仍是可由用户配置的 Agent 设置。它没有成为管理员强制的、恶意用户不可关闭的租户边界。

## 相对一致性

| 项目 | Linux | macOS | Windows |
| --- | --- | --- | --- |
| Agent 设置、审批、KEEP Y、禁止严格提权 | 同一后端逻辑 | 同一后端逻辑 | 同一后端逻辑 |
| 命令隔离 | SRT/bwrap；不兼容时 auto 选 Landlock | SRT/Seatbelt | SRT 0.0.78+ 专用账号、ACL、WFP；上游 alpha |
| 严格文件工具 | 目录 FD、O_NOFOLLOW、原子替换 | 相同 POSIX 实现 | 原生 HANDLE 固定父目录，拒绝 reparse/junction，原子替换 |
| 严格 Web | 相同域名/端口许可、公网 DNS 验证、代理连接 | 相同 | 相同 |
| 宿主浏览器回退 | 严格模式禁止 | 严格模式禁止 | 严格模式禁止 |
| 基础资源 | rlimit；受控网络执行时增加 systemd/cgroup | rlimit | Job Object：CPU、整组内存、进程数、墙钟 |
| 进程可见性 | 后端不同；Landlock 严格模式隐藏环境、内存与命令行 | 系统沙盒规则 | 原生账号与 Job；交互命令暂不支持 |
| 验证 | 本机单元、真实文件与代理、真实 Landlock | 接口和策略检查，缺少真机 | 接口测试；原生测试加入 Windows CI，本机无法运行 |

SRT 是通用策略接口，底层系统和保护能力不同。相同配置不代表所有操作系统提供完全相同的安全保证。[上游说明](https://github.com/anthropics/sandbox-runtime#how-it-works)。

## 本次补上的边界

- 以前 Web 只有审批，没有严格模式的网络硬边界。现在运行时预审、统一审核和 MCP 执行入口都会检查严格许可，已发出的执行许可也不能绕过。
- HTTP、DDGS 搜索连接经同一公网代理。许可检查先于 DNS；所有解析地址必须公开可路由，连接直接使用已检查的数值地址，避免二次 DNS。HTTP 重定向仍经过代理，不继承 `HTTP_PROXY/NO_PROXY` 绕行。
- 普通模式浏览器也配置公网代理并关闭隐式 loopback 绕行；严格模式直接禁用宿主浏览器，避免把网页脚本当作可信的后端代码。
- HTTP 解码结果限制 2 MiB，避免无限正文在宿主内存中累积。
- 严格文件读取拒绝多硬链接普通文件；写入替换新文件，不通过已有链接修改外部 inode。Windows 不再因缺少 POSIX API 而一概拒绝，改用真实文件句柄固定路径；设备名、ADS 流、UNC 共享与 junction 拒绝。
- Landlock 严格进程信息不再提供 `cmdline`，避免泄露命令行中的密码或令牌。
- 自定义策略 hook 原本能在宿主运行 shell，或向任意日志路径追加文件。严格模式现在禁用这类自定义 hook，保留基础 allow/deny 策略和固定后台审计记录。普通模式的 hook 仍需将配置者视为可信操作者。

## 对恶意用户或恶意模型 API 的剩余风险

以下是源码审查发现的边界，不能靠审核提示词消除。

### 高优先级：配置权仍属于普通登录用户

`server.verify_auth_or_token` 只检查用户密码或内部令牌，没有管理员角色判断。`ops/settings_service.py` 的全量配置更新、重启等入口使用这个检查；配置表单的 host 范围也没有独立的管理员授权。拥有有效用户凭证的人可调整主机配置，包括 LLM 连接目标；对不可信多用户部署，这是明确的控制平面风险。

用户也能调整自己 Agent 的安全等级或创建普通模式 Agent。因此“严格模式下禁止提权”不等于“用户无法通过另一个 API 关闭严格模式”。需要管理员与成员角色、受保护的主机安全下限以及所有配置入口的一致授权。此次未擅自更改现有用户角色或主机设置。

### 高优先级：外部 CLI 的原生工具不受 ClawCross 工具沙盒约束

Codex/Claude 通过 MCP 调用 ClawCross 文件、Web、command 工具时受本项目限制。但原生 exec/read/web、CLI 插件和外部 HTTP agent 由自己的运行环境约束。设置本项目的严格模式不会自动给整个外部 CLI 进程套上本项目的 OS 隔离；acpx 的审批旗标也不是 OS 隔离。不能向用户声称一个严格 Agent 的所有原生能力都已被限制在同一工作区。

### 平台差异：SRT 的宽读模型与 Landlock 严格白名单不同

当前 `_policy` 明确隐藏用户 home、后端配置和严格模式的项目源码，但仍保留 SRT 的“默认可读、指定路径拒绝”模型。系统其他目录中的可读文件不一定被隐藏；Linux 新 PID 的敏感 `/proc` 路径也不能仅靠启动时的路径枚举保证永远覆盖。Windows 专用账号能读取什么还取决于宿主原有 ACL，以及上游共享账号的隔离行为。

本机 Landlock 严格模式使用允许读取的系统运行目录和独立工作区，已验证环境、内存、命令行和工作区外合成文件被拒。SRT 的严格全盘读白名单需要在各平台真机验证；不能把这项差异仅用相同 JSON 设置掩盖。此次没有在未经真机验证的情况下给 Windows 整个系统盘添加拒绝 ACL。

### 高优先级：委托给其他 Agent 的权限继承仍有缺口

`mcp/webot.py` 的 `spawn_subagent` 目前继承父会话的交流/审核 mode，没有同时继承 `sandbox_security`、沙盒后端和网站许可；`send_subagent_message` 继续使用目标会话自己的设置。严格 Agent 因而可能委托一个权限更宽的 Agent 代为操作。这是对恶意模型 API 的实际能力边界缺口，不能只依靠每个文件/Web 工具的局部检查。

需要在新建子 Agent 时继承权限上限，并在跨 Agent、群聊和工作流委托时检查目标范围，防止绕过父级限制。现有群聊/委托语义此次没有整体更改；未对线上 Agent 发出攻击或测试委托。

### 可用性与资源：仍可能拒绝服务

每条命令的限制不等于整个用户或服务器的配额。工作区没有总容量/文件数量配额，API 没有在此次任务中补齐租户并发与请求速率上限；反复创建任务或大量小文件仍可能耗尽资源。Windows 没有对应每文件大小、FD 上限；macOS 与无 cgroup 的 Linux 缺少相同的整组限制。

Landlock 不是完整虚拟机；部分文件元数据或系统状态仍可能可见。SRT 和内核本身的漏洞不在应用白名单可消除的范围内。

### 恶意 API 已经收到的内容不能靠沙盒收回

模型只应得到用户愿意发送的对话、文件和工具结果。API 提供者本身不可信时，已发给它的内容已经越过数据边界；沙盒能限制后续工具动作，不能保护已传出的原文。密钥表单只返回填写状态的机制应继续保留。

## 验证方法

`test_web_security.py` 用合成 DNS 与本地 HTTP 端点验证许可、端口、重定向、DNS 重绑定防护、空身份、并发 Agent 状态隔离、浏览器禁用和正文上限。真实 HTTP 代理测试只将合成公网入口映射到测试端点；内网目标没有被请求。`test_confined_files.py` 在各平台执行真实文件读写、硬链接和 symlink/junction 攻击；Windows 的目录锁定测试要求 Windows 内核。

Windows CI 加入真实文件句柄测试，默认仍不安装或初始化 SRT。完整 Windows SRT 测试需管理员显式准备，然后开启 `CLAWCROSS_WINDOWS_SRT_INTEGRATION=1`。本机通过不能替代尚未运行的 Windows/macOS 真机验证。

本次本机结果：主要组合 169 项及 58 项子测试通过；hook/文件/Web 专项 42 项通过；最终路径绑定与文件/策略专项 36 项通过；正式 Landlock 资源与私有进程信息测试 1 项通过。这些组合包含重复用例，不相加。真实公网 HTTPS 抓取 example.com 返回 200。Windows 内核相关用例在 Linux 跳过；没有通过模拟来宣称 Windows OS 隔离已完整验证。
